# Downtime tab (Shadowdark carousing and downtime)

The tab shows only while the System is `'shadowdark'` (`applyDowntimeTab()` in js/downtime-ui.js,
called from `renderSettings()`; it closes the tab, or the split pane, when the System changes).

## Files

| File | Contents |
|---|---|
| `data/downtime-shadowdark.json` | The rules data (generated; see below): `eventSets`, `settlements`, `warbandLimit`, `activities`, `related`, `rules` (full section text as blocks), `tables` (by id), `classes` (hit die and spellcasting stat by class name), `potions`. `OSR.data.downtime` (js/data.js). |
| `js/downtime.js` | Pure rules engine, `OSR.Downtime` and `module.exports`. Every function takes `rng` (default `Math.random`). |
| `js/downtime-ui.js` | The tab: render, delegated listeners (`wireDowntime()`), sheet ↔ record. |
| `test/downtime.test.js` | Engine tests (fixed dice) and the tab in jsdom. |

`data/downtime-shadowdark.json` is generated by the `shadowdark_companion` repo:
`node tools/export_keeper_downtime.ts` there (the default output is `../osr_keeper/data/`). Do not
edit it by hand. The owner bundles this Shadowdark text by decision (2026-11-09), like the WWN free
edition (AGENTS.md "Hard rules").

## Party

The party is the campaign's Shadowdark characters (`charSystemKey(ch) === 'shadowdark'`).
`pcOf(ch)` (exported as `OSR.downtimePc`) merges:

- **The trackers** `"Luck (Name)"` and `"GP (Name)"` (js/core.js `syncResourceTrackers`), made
  from the sheet line `> **AC** 11 · **HP** 5/5 · **Luck** 0/1 · **GP** 5/0 · **XP** 0` (the
  layout of `data/gulzund-blize-shadowdark.txt` and of the Shadowdark Companion's "Copy for RPG
  Keeper" text). Luck max 1 (core p. 79: one luck token per player); GP max 0 = no limit. When a
  tracker exists, it holds the luck tokens or the wealth; the sheet number is only the start value.
- **The sheet** (`Downtime.readSheet(body, classes)`): `Level N`, `**XP** N` (or `XP: N`),
  `**Luck** N` (or `**Luck** 🍀 N`, `Luck: N`; used only without a Luck tracker), the six stat modifiers (an ability table `| STR | 8 | -1 |`, else
  `STR +1` / `STR: +1`, else a score), and the class (the longest class name in the first lines →
  `classes[name]`).
- **The record** `state.downtime.records[ch.id]` (`Downtime.newRecord()`): `gp`, `renown` (`null`
  until set: it starts at the CHA modifier, PGWR p. 233), `failures` (`'<activity>.<option>'` →
  count), `ongoing` (contacts, debts, items, lasting effects), `log`, `carouseMod` (standing),
  `nextCarouse` (one time), `benefitAdv`, `cancelMishap`, `usedDowntime`, `bardAdv`, `jeweledEye`,
  and optional `hd` / `caster` overrides (`''` = from the class). XP and luck are in the record only
  when the sheet has no such number (and, for luck, no tracker). `gp` in the record is the wealth
  only without a GP tracker; with one, `commit` copies the tracker value there too.

`commit(pc)` (exported as `OSR.downtimeCommit`) writes luck and gp into their trackers
(`clampConsumable`: luck stays at 1 or less), XP and tracker-less luck into the sheet
(`Downtime.writeSheetNumber`, every occurrence), and the rest into the record. `finish()` re-renders
the Trackers panel; a tracker change in the Trackers panel re-renders the Downtime tab. Undo restores
the records, the sheet bodies, and the Luck and GP tracker values. Level up (`writeLevel`) sets XP to 0 (core p. 117) and adds 1 renown with
the Western Reaches rules on. `ensureDowntimeShape()` (js/core.js) backfills the record fields and
`state.downtime.ui` (`DOWNTIME_UI`), and drops records of deleted characters.

`state.downtime.ui` holds the form choices: `wr` (Western Reaches rules: renown, settlement limits,
the four WR activities, warbands), `oneToOne` (WR GM p. 34 durations), `kind`, `settlement`,
`eventIdx`, `ids`, the group bonuses, `treasureRules`, `library`, `checkPc`, the rumor target, the
warband level, and the Wizards and Thieves form.

Per page load only (not saved): the last results, the last check, the last game, table highlights,
and **Undo** (`snapshot(label)` keeps the records and the bodies of the party before a change).

## Engine

- `carouse({ data, set, event, pcs, ids, group, useRenown, treasureRules, oneToOne, rng })`: each
  PC in `ids` pays `ceil(cost / n)`, rolls 1d8 + event + group + renown + one-time + standing. Core
  and GM Companion sets read the outcome row's text with `applyText()`. The Western Reaches set
  reads the columns (Mishap, Benefit, d100 Modifier, XP) and rolls the d100 tables
  (`resolveD100`, with "re-roll as mishap/benefit", benefit ADV, and the canceled mishap). Renown,
  the bard talent, and the brewery apply to carousing only, not to the GM Companion alternatives.
- `applyText(data, pc, text, ctx)`: XP, `N% of your wealth`, flat gp losses and wins, debts, renown
  (not when "if anyone sees it"), luck tokens, next carousing roll, benefit ADV, canceled mishap,
  treasure rolls (`80-100 item`, `2x rolls on Treasure 4-6`, `+20 … one up from your LV`, …),
  two random potions, a random rumor. Each change returns a line; the narrative goes to `ongoing`.
- `downtimeCheck({ pc, activity, option, library, rumorTarget, oneToOne, rng })`: pays the cost,
  d20 + the best allowed stat (or the spellcasting stat), ADV from the bard talent (and the Jeweled
  Eye on learning activities), +1 library on learning activities. A failure lowers the DC one step
  (`loweredDc`, never below 9); a success resets it. A rumor about another PC returns `rumor`.
- `recruitWarband`, `wizardsAndThieves(players, ante, rng)` (core p. 94; random calls).
